# API и операции ППО ID Docs

## Границы доступных сведений

ППО ID Docs — реальная система, развёрнутая и работавшая в офисной серверной инфраструктуре. В проекте использовались API-операции, JSON-обмен между сервисами, прямые SQL-запросы АРМ МС к Oracle и операции прикладного кода.

**API-маршруты относились к реальной работающей системе.** Публичный репозиторий не содержит полного набора внутренних конфигураций и исходников маршрутизации, поэтому в документации приводятся только конкретные пути, которые можно связать с доступными проектными материалами. Отсутствие этих конфигураций в публичном репозитории не означает, что маршрутов не существовало или что система не работала.

Эта страница систематизирует API-операции и сведения о взаимодействии реальной системы. Она не заменяет полный внутренний контракт API и не раскрывает закрытые адреса, конфигурации или данные.

## Документированные операции и символы кода

| Элемент | Что указано в доступных материалах | Статус |
|---|---|---|
| `issueNewDocument` | Сценарий создания нового документа с привязкой к делу и лицу | Упомянут в описании исходного кода; точный внешний контракт не установлен |
| `RollbackScenario1` | Сценарий отката, для которого в описании кода отмечена отправка пустого объекта | Поведение требует проверки по полному коду вызывающей стороны и обработчика |
| `getCountryDictionary` | Метод получения справочника стран; в описании исходного кода отмечено, что клиент его не вызывает и использует локальный `dict_country.csv` | Метод присутствует в описании исходного кода; данный клиент использует локальный `dict_country.csv` и не вызывает сетевую операцию |

Имена методов и пути, встречавшиеся в прежних редакциях страницы, следует публиковать в точной форме исходных проектных материалов. Их отсутствие в текущей публичной выборке не является свидетельством отсутствия таких операций в рабочей системе.

## Формат взаимодействия

- **JSON:** формат обмена между сервисами указан в существующих материалах; конкретные участники, схемы сообщений, направления и версии контрактов требуют отдельной проверки.
- **SQL:** для АРМ МС документированы прямые обращения к Oracle.
- **Oracle:** таблицы и поля описаны в разделе [«База данных и модели»](../database/); наличие таблицы само по себе не доказывает, что она используется конкретной операцией или endpoint-ом.

## Связь операций, моделей и таблиц

Раздел [«Исходный код и модели»](../source-code/) содержит сопоставления отдельных моделей и провайдеров с таблицами Oracle. Раздел [«База данных и модели»](../database/) описывает структуру таблиц и полей.

Эти материалы обеспечивают навигацию и анализ прослеживаемости между API, моделями и БД. Детальные соответствия JSON-полей столбцам, последовательности вызовов и транзакционные сценарии описываются по тем проектным материалам, которые относятся к конкретной операции. Историческая система работала на офисных серверах; повторный доступ к серверной среде с персонального ноутбука для подготовки этой документации не выполнялся.

## Версионирование и конкурентный доступ

В отдельных описаниях таблиц встречается поле `VERSION`. Наличие и назначение этого поля необходимо проверять для каждой таблицы отдельно. Доступные материалы не дают оснований утверждать, что поле присутствует во всех таблицах ядра и миграции или что оно обязательно передаётся каждым API-запросом.

## Откат операций

В описании исходного кода для `RollbackScenario1` отмечена отправка пустого объекта. Этого недостаточно, чтобы утверждать, что откат выполняется хранимыми процедурами или триггерами Oracle. Механизм транзакции и фактическая последовательность отката требуют проверки по реализации.

## Что необходимо для подтверждения API-контракта

1. Исходники контроллеров, обработчиков сообщений или иных точек входа.
2. DTO/модели запросов и ответов с атрибутами сериализации и валидации.
3. Конфигурация маршрутизации и транспорта.
4. Реализации провайдеров и транзакционных сценариев.
5. Тесты или трассировка, подтверждающие фактическое поведение.

Внутренние конфигурации и закрытые адреса не публикуются. Это ограничение публичного комплекта документации, а не характеристика реальности или работоспособности API.
