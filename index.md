# ППО ID Docs — архитектура, база данных, API и исходный код

Портфолио-группировка: Territory / Rexoft. В доступных технических материалах система обозначена как ППО ID Docs.

ППО «Территория» ФМС — отдельная система; её документация находится в [отдельном архиве](https://github.com/ekatmoz88-alt/ppo-territory-archive). Не смешивать архитектуру, Oracle-модель и интеграции этих систем.

Комплект технической документации по ППО ID Docs охватывает логическую архитектуру, информационную базу Oracle, предметные модули учёта, программные компоненты и API-операции.

## Навигация по разделам

- [Архитектура системы](./architecture/) — системный контекст, границы, программные компоненты, модель данных и потоки операций с явными статусами доказательности.
- [База данных и модели](./database/index.md) — структура БД Oracle, ядро (`CORE_*`), справочники (`DICT_*`), предметные модули, связи и ER-материалы.
- [Исходный код и модели](./source-code/index.md) — архитектура проектов (`Umms.*`), основные модули ПО СС/ПО МС, сценарии и сопоставление моделей кода с таблицами БД.
- [API и операции](./api/index.md) — JSON-операции, лица, документы, миграционный учёт, сопоставление полей запросов с таблицами БД, валидация и откат.

## Общая информация

Информационная база ППО ID Docs предназначена для автоматизации учёта граждан, документов, регистрации и миграции. Модель реализована в Oracle и включает 401 таблицу: 44 таблицы ядра `CORE_*`, 104 таблицы справочников `DICT_*`, остальные относятся к предметным модулям.

- **Формат обмена:** JSON между сервисами; для работы АРМ МС в материалах также описаны прямые SQL-запросы к БД.
- **Поле VERSION:** встречается в отдельных описаниях таблиц; наличие и назначение следует проверять для каждой таблицы отдельно.

## Ограничения

Документация не заявляет о проверке работающей production-инсталляции. Логические схемы, описание API и сопоставления моделей с таблицами ограничены доступными проектными материалами и просмотренными исходными фрагментами. Физическая топология, полнота интеграций и runtime-поведение требуют отдельной верификации.
